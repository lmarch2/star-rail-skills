# 星穹铁道宝箱收集

目标是完成用户指定区域或目标中的实际收集，并用游戏内计数或奖励状态核验。不要把执行完一条路线等同于全图收集完成。

## 复用现有能力

- 涉及小助手安装、版本、活动任务、运行控制或 OCR 命令时，先使用 `march7th-assistant` 技能。检查 `--status` 与活动任务，避免重复启动；官方任务通过 `m7a.exe` 运行，`elevation: task` 时复用用户已开启的免 UAC，无需再请求确认。源码里的新能力不一定存在于已安装版本；安装版的免 UAC 不自动适用于另一个源码目录或直接启动的 Python 控制器。
- 在源码仓库工作时，先看 `assets/docs/Treasure.md`（使用方式与限制）、`tasks/exploration/treasure.py`（开箱确认）和 `utils/treasure_map.py`（SIFT 定位与航点移动）。优先复用现有 `treasure` / `treasure_nearby`、记录路线、地图定位、OCR 和开箱确认；不要另写一套已有功能。
- 先记录游戏地图上的总数和分类进度，再选现成路线。路线执行成功只说明该路线步骤完成；Fhoe-Rail 巡回也不保证覆盖全部宝箱。按用户目标补查遗漏，并保留 `opened`、`unresolved`、`pending` 的实际状态。

当前路线验证结果查 `assets/treasure_routes/life_sciences_institute/README.md`，当前问题查 `docs/星铁导航卡点.md`；不把历史失败或缺少新箱正样本当作当前阻塞。实际开箱仍按下述奖励与交互状态确认。

## 识别、移动与开箱

- 文字信息优先用本地 OCR 获取，例如源码版 `python main.py --observe` 或 `--observe-image`。用于地图计数、交互提示、奖励、任务阶段和对话文字；不要把每次移动后的整张画面都发给模型。
- 只有 OCR 不能表达地形、平台、机关方向或落点时，才查看必要截图。观察画面前先确认游戏捕获正常；游戏权限较高时，使用前台捕获或相同权限的终端。
- 普通 3D 宝箱必须看到准确的宝箱交互提示。优先调用现有开箱逻辑；确认旧奖励状态已清除，随后出现新的“星琼”奖励且宝箱提示消失。只有位置接近、按过交互键或路线走完都不算成功；证据不足时标记未确认。
- 地图定位前核对区域、楼层、分辨率、缩放和起点。已验证范围与路线状态以 `assets/treasure_routes/life_sciences_institute/README.md` 为准；换到未验证的楼层或地图布局时先验证，不要沿用未经验证的像素坐标。蓝色角色箭头靠近目标不代表实际可达，栏杆、家具和花坛都可能挡路。
- 定位失败、角色连续无进展或交互对象不符时停止重复输入；检查楼层、镜头与障碍，重新定位或规划绕行。到达任务标记也不代表找到正确对象，核对精确交互提示后再操作。
- 巡回优先使用现有移动后的 OCR 回调和终点检查，开箱未确认就停止；不要另写持键期间的 OCR 循环。管道等地图坐标不反映位移的场景，复用已录制移动与终点模板，不依赖 `map_move` 反馈内部进度。

## 特殊目标与续跑

- Jump、小型解谜、剧情、隐藏房间和狸狸任务不一定支持普通 3D 自动开箱循环。按实际玩法分流：OCR 追踪阶段、提示和对话；只有视觉几何无法由文字判断时再看截图。传送、对话选项或机关操作后先确认阶段已变化，再决定下一步；不要在状态未确认时重复交互。带冷却或时序的目标按画面状态等待，不要连发输入。
- 源码已提供 `interact`、`wait_for`、`jump`、`gold_balloon` 路线步骤，格式和限制见 `assets/docs/Treasure.md` 的“特殊交互与小游戏”。交互只点击精确目标一次，再等 `expect`；传送两端共有的“传送”提示不能证明已经到达，须用目的地特征。NPC“调查”与相邻设施也要区分。
- Jump 用 `when` 核验起跳点、`expect` 核验角色落点；连续持方向并按时单跳或双跳，失败即释放，不补发迟到动作。平台位移与条件需实机标定；固定背景同时出现在起点和终点时不能作为落点证据。
- 金气球优先复用 `utils/treasure_balloon.py` 及 `gold-balloon-4718.png`，不要重写缓存中的临时脚本。它只支持已标定的 `4718` 机位和时序：确认下降后右键发射，遵守冷却，并等待新成功提示。后端输入失败停止，避免把部分发射误当作未发射重试；发射次数不等于成功数。新接口的离线测试不代表已有完整可回放的小游戏路线。
- 被暂停、游戏重启或用户手动移动/转镜头后，先检查是否已有活动任务，再重新观察当前地图和角色位置；只有状态可靠时才续跑，不要另起并行任务。
- 完成时重新读取地图总数及相关分类计数，并对照起始值、目标清单和未确认项。收集总数达到目标才报告完成；否则列明已确认、未确认和阻塞位置。只有用户明确要求时才在结束后关闭游戏。
