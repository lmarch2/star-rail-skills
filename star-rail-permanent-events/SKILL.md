# 星铁常驻活动完成

目标是完成用户指定范围内的活动流程、目标和奖励领取，以游戏内状态核验。将本技能用于不同活动时，重新读取当前规则和界面；角色、阵容、坐标、关数、等级上限、奖励数量及最优打法都属于本次活动状态。

## 接管与范围

- 复用用户已给出的活动名称、截图、进度和授权。代做活动且没有保留剧情要求时，优先跳过可跳剧情；普通推进对话可选择任一可继续项。用户要求看剧情或指定选项时服从其偏好；剧情随意选择不等于奖励自选也可随意选择。
- “完成活动”默认覆盖该活动的主流程、常驻目标及对应可领取奖励。用户只要求剧情、某关或某种奖励时缩小范围。不要自动扩展为排行榜、自由联机、全收藏、所有隐藏成就或已经结束的限时任务。
- 涉及小助手时读取 [march7th-assistant](../march7th-assistant/SKILL.md)，按其安装登记、`--status` 和任务列表定位当前可用能力。优先已有专用任务或已验证流程，通过 `m7a.exe` 运行；`elevation: task` 表示用户已开启免 UAC，无需再请求确认。源码里有某能力不代表安装包已经支持；自定义控制会话的权限与启动方式见 [常驻会话用法](references/session-control.md)。找不到专用任务时复用观察、输入、剧情和战斗能力，按阶段推进。
- 同一时刻只保留一个游戏输入控制者。检查小助手任务和本会话临时控制程序，已有合适任务就接续；辅助代理可并行查资料或代码。开始调用自定义控制、处理空间解谜或排查输入时读取 [控制与效率参考](references/control-and-efficiency.md)。

## 找入口，先看如何完成

1. 已在目标活动中时直接接续。否则通过当前可见的活动入口、任务追踪或 NPC 交互进入，先确认名称匹配。
2. 常驻活动可从手机菜单的“旅情事记”查找。已观察到的入口路径是“旅情事记 → 奖励指南 → 常时传略 → 活动详情 → 继续游玩/前往”；它是查找线索，以当前界面的实际名称为准。找不到时查看页面分类、筛选和任务列表，不凭记忆连续试快捷键。
3. “前往/继续游玩”可能只打开地图。完成传送后核对目标 NPC、交互提示或玩法入口，不能把到达地图标记当成已经开始活动。移动时核对区域、楼层和障碍；必要的宝箱或探索环节可复用 [treasure-opening](../treasure-opening/SKILL.md)。
4. 开始推进前看一次活动进度和奖励页：当前章节、解锁条件、挑战目标、等级/积分/经营指标、已达成未领取项、剩余奖励。区分常驻与限时内容，确认这次需要达到的实际终点。
5. 先领已经满足条件的奖励，检查经验、积分是否需要“提交/升级/结算”，以及是否有“一键领取”。进度数字不变时先查机制，不能直接推断资源不足而额外刷关。

只记录后续决策需要的状态：活动、当前阶段/页面、目标、已完成与待领项、直接前置、下一步。长任务在已有会话工作记录中保存最近确认的状态和有效操作参数，便于中断后恢复，不为每次点击建记录。

未解锁时读出确切前置。直接属于该活动的短前置继续完成；若要转入大段其他主线或用户未指定的活动，说明依赖和新增范围后再决定。用户已明确授权相关前置时直接推进。

## 按当前阶段执行

| 阶段 | 操作方式与阶段结束证据 |
|---|---|
| 剧情、普通对话 | 复用自动跳过与点击能力；可跳过则跳过，不可跳过则推进文本和普通选项。出现任务更新、活动主页、战斗或需要决策的玩法后切换控制方式。 |
| 强制教程 | 按高亮对象和提示逐步完成。教程遮罩可能拦截空白点击、返回和其他按钮，先完成当前教学动作。 |
| 普通角色战斗 | 检查阵容和可用试用角色，开启游戏内自动战斗及可用加速，并确认已开启。自动功能锁定时按教程或必要操作推进，解锁后再开。等待胜负结算；新模式可能不继承自动状态。失败后根据原因调整阵容或操作，不重复启动相同失败方案。 |
| 探索、交互、解谜 | 用任务提示和地图定位；交互前核对对象，操作后看目标/机关是否变化。文字不能表达路线、图形或空间关系时才查看必要截图。 |
| 卡牌、棋盘、经营、节奏等专属玩法 | 先读胜利条件、资源作用、回合顺序和教程，选择能稳定达标的简单策略。普通战斗的“自动”不能覆盖这些玩法；仅在玩法本身有自动/托管且适合目标时使用。 |
| 结算、升级、领奖 | 处理结算和奖励弹窗，读取下一阶段或未完成目标；检查是否需要交付、升级、提交成绩或手动领取，然后继续。 |

专属玩法优先使用推荐、试用或已验证有效的配置，检查进入新关后是否继承阵容、卡组、道具和难度。首次理解规则后形成简短决策规则并复用：先判断能否直接达标，再选择足够好的行动；仅在新机制、失败或明显无进展时深入分析。用户偏好激进、快速时减少低收益优化，优先更短的达标路径。

**能赢就直接收局：** 已有明确可执行的获胜方案时，立即停止精细计算伤害、收益和最优组合，按必要顺序完成行动并确认胜利结算。足以判断胜负的简单比较即可，不必把所有方案算完；仅当额外分数或条件影响用户目标、奖励，或新情况改变胜负判断时再计算。

## 视觉线索、查询与决策

- 礼物、宝箱、星琼图标和红点只说明值得查看，不能单独证明奖励可领；核对“奖励预览/剩余”“领取/已领取”等文字与状态。任务标记用于定位，靠近后的对象名称、交互按键提示用于确认动作。教程高亮优先于普通界面。遇到陌生图标或状态不明确时，读取 [视觉线索与决策参考](references/visual-cues-and-decisions.md)。
- 缺少机制、前置或路线事实时，先看当前游戏说明和提示，仍缺再定向查网络；足以影响下一步且继续试错耗时明显时就查，不必等反复失败。开放与奖励范围查官方说明，具体解法查匹配当前常驻版本和阶段的攻略，空间问题用图文或视频；控制程序问题查当前源码、日志及对应版本文档。查找方法见同一参考。
- 规则已明、输入已验证、普通行动可低成本纠正且只需达标时，直接使用有效策略、推荐配置、自动战斗和已验证的操作批次。已能达标就执行，不逐项比较所有方案，也不为每关重新搜索攻略。用户偏好快速时优先减少决策与工具往返，不盲目缩短游戏实际需要的等待。
- 新机制、关键条件变化、失败原因不明或操作生效却无进展时暂停批量操作，自己分析当前证据：目标是什么、缺哪个条件、下一步预计改变什么。事实齐全就选择一个关键改动验证；事实缺失则查询。输入问题转到控制排查，动画和自动战斗仍在推进则等待；不要把所有卡点都归为策略不够好。

## 高效率操作

- 路径移动优先复用本地定位和路线执行：先检查当前区域是否有可用的地图标定、路线数据和执行入口；匹配时交给本地定位、移动与纠偏循环。模型负责机关、分支和异常判断，缺少适用标定时再用看图与地标推进。具体入口与适用条件见 [本地定位与路线执行](references/control-and-efficiency.md#本地定位与路线执行)。
- 常规阶段由本地 OCR 或已有图像匹配读取文字、按钮和状态；复用持久进程及模型实例。只有布局、图形、图标或 OCR 歧义影响决策时才查看截图。
- 每轮只取足够决定下一步的信息。同一稳定界面内，把已确定的多个选择合成一批输入，在批次末尾检查一次；已验证且无需中间判断的界面转换也可合批。出现未知弹窗、未验证布局或需要重新定位时先观察，不要每点一次都做全屏 OCR、回传截图和重新分析。
- 入口切换、传送、提交、战斗结算和领奖后检查预期变化。动画期间按阶段等待，到预计可操作时再检查按钮/状态；避免不断识别动画中间帧或一律等很长时间。
- 重排、滚动、缩放、道具改变布局后重新取得目标位置。复用的是已验证的识别方式和策略，不是已经失效的屏幕坐标。
- 无进展时先确认画面和输入是否有效，再修改玩法策略。相同操作重复无效就换诊断方向；停止堆叠盲点、盲按和重复开局。
- 将有进展的结果用于下一次决策。只在卡点实际发生时细分输入、OCR、动画、工具往返或模型分析的耗时，不提前建立复杂性能系统。

## 领奖与收尾

- 按活动实际提供的栏目检查：任务/章节奖励、积分或等级奖励、挑战目标、结算奖励，以及活动兑换奖励。达标后需要点击的“提交/升级/结算/领取”也属于完成流程。
- 根据剩余奖励和目标决定补做什么；优先补能推进目标的关卡或条件。资源已足够时先提交，避免多刷。不要默认每个活动都需要满级、满分、全收集或联机。
- 活动专用且可再获得的资源可以在已授权的玩法内使用；星琼、付费货币和通用稀缺养成资源的额外支出不包含在普通代做授权中。奖励自选或有限代币的互斥兑换按用户已有偏好处理；有实质取舍且偏好未知时，只询问该项。
- 分别核验关卡、活动流程和奖励：关卡通关后检查是否解锁尾声、交付或返回 NPC 的任务；流程结束后确认对应奖励已领取；最后回到活动进度与奖励页核对范围。页面提供百分比或完成标记时一并核对，没有时用任务与奖励状态确认，不强求所有活动都有同一种完成界面。剩余星琼可辅助核验，但不能代替非星琼奖励和流程状态；限时过期、未解锁与已领取也要区分。
- 不能仅因脚本返回成功、对话结束、单场胜利或弹出一次奖励就报告整个活动完成。仍有阻塞时，报告已完成部分、准确位置、剩余目标和原因。
- 完成后停止本次启动的临时控制与自动对话，释放按键，默认保持游戏打开。用户已要求完成后关闭游戏时，沿用该要求，无需再次询问；先核验活动完成，再正常关闭游戏和本轮控制进程，按 [常驻会话收尾规范](references/session-control.md#收尾与退出) 确认退出。恢复本次临时改动的设置；不停止无关任务。简洁汇报实际完成范围和已确认的奖励，不凭预计数量报领取结果。

暂停、工具超时、断线或用户手动操作后，先检查仍在运行的任务及当前游戏状态，再从最近确认的阶段继续。工具超时不代表动作未执行，领取、提交或消费操作不能盲目重放。
