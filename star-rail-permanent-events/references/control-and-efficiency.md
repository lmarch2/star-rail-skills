# 控制、识别与等待

实际代做活动、探索、宝箱或开展自定义游戏控制时，执行者必须在首次游戏操作前完整读取本参考；由子代理执行时，由该子代理先读。同一任务已读过且内容仍在上下文中时不重复全文读取，后续按问题回查相关章节。

仅查询状态、查看日志或直接启动小助手已封装的日常任务时，按需读取；若转入自定义控制或输入排查，须在该环节开始前读取。

参数是校准起点，不是所有设备和活动的固定值；依据当前工具和源码接口执行。

## 先复用，再补最小控制

- 按 `march7th-assistant` 技能定位安装目录与能力，用其状态和运行记录接续已有任务。注册中的旧源码路径可能已不存在，先核对路径，不反复调用失效入口，也不全盘搜索。
- 一次观察可使用当前版本支持的 `--observe` / `--observe-image`；持续交互优先复用常驻 OCR、截图和输入对象，避免每步启动 Python、加载模型或重建游戏连接。
- 没有专用任务时，只补本次缺少的控制操作。批量输入与观察应可分开：若每条输入都自动附带全屏 OCR，应增加“不观察的输入批次＋末尾一次观察”，不能只把工具调用包装在循环里就认为已经减少识别。
- 临时控制程序使用独立目录，不因代做活动改动主项目、用户默认配置或安装新插件。只有重复出现且稳定的需求才值得形成通用脚本。
- 游戏与控制进程权限不匹配时先确认捕获、输入失败的具体位置，复用小助手提供的启动方式；必须出现的 UAC 或首次使用确认遵循相应工具规则，不能绕过。临时后台程序使用隐藏窗口。

## 事实、实现与验收

- 代码字段为空、当前接口未提供某能力，只能说明实现状态；涉及游戏界面和按键效果的判断先核对截图或一次可逆实测，不能据此断言游戏没有显示或不支持。M大地图实际显示相机扇形。
- 新增识别依赖前，先检查已有定位结果和已验证的原生操作能否满足需求。只有原生操作确实建立了状态等价关系时才复用已有量，例如本次回正后可用人物朝向表示相机朝向；不能把这个条件关系扩展成任意状态下二者相同。
- 用户要求自动行为时，确认改动已接入实际执行入口；更新规则或手动成功不算自动实现。先用已走通短路段验证该功能，再验证复杂目标；分别报告输入生效、位置与楼层确认、到达、交互和活动完成，保留原失败目标的未解决状态。

## 按启动能力复用会话

持续交互复用常驻控制会话，启动前检查是否已有可用会话，保持单一游戏输入控制者。官方 `m7a.exe` 任务在 `elevation: task` 时免 UAC；直接运行的自定义 Python 控制器仍按自身权限启动。启动、必要的 UAC 确认、所有权交接、版本能力、请求格式、超时接续及退出统一见 [常驻会话用法](session-control.md)，本参考只说明控制策略与诊断。

## 输入校准和坐标

首次接管、窗口变化或恢复后，读取游戏窗口位置、截图原始尺寸与缩放，选择一个可逆动作确认输入生效。有效参数可在同一布局下复用。

- 将 OCR、截图与点击坐标放在同一坐标系。缩略图只用于观看；坐标换算按实际宽高比例分别进行，裁剪图还要还原裁剪偏移。输入后端若已经做坐标换算，不再重复换算。
- 快速点击偶发遗漏时，先核实界面可操作，再尝试带短暂停留的按下/释放。约 100～200 毫秒可作为鼠标起点；键盘交互仍漏触发时可适当延长，例如 300～500 毫秒。本次环境有效不代表数值对所有游戏阶段都必要。
- 正常使用当前后端支持的按键名称和输入方法。需要短按时优先直接使用有时长的点击接口；没有时，可在确认语义相同的后端使用同点按下/释放等实现。
- 3D 场景可能捕获鼠标，不能假设可直接点击 HUD；根据当前提示使用交互键或该界面提供的鼠标操作方式。
- 操作完成或控制异常退出时释放已按住的键和鼠标按钮。用户手动操作后重新读取当前状态，不能继续发送旧坐标序列。

## 本地定位与路线执行

- 普通地图移动优先调用**无预录路线导航**：`tasks/exploration/navigation.py::run_navigation`，共用入口为 `TreasureGame.navigate`。开图确认目标与楼层后，用当前地图全画面的归一化坐标指定目标；程序建立底图、标定方向、规划路径并核验位移。没有该地区的预录路线或底图，不是退回手动盲走的理由。入口和当前验证范围见仓库 `assets/docs/Treasure.md`。
- 大地图和小地图上的可走地面只是路线候选，可能漏画培养罐底座等实体。确认受阻后停键查看主画面，侧移候选读取足旁地面，不能把物体立面当通路；颜色候选也不证明实际可通，逐段用可靠地图位移核验。前台入口保持同一侧短段绕行，看到前方通道并核实自由前进后才恢复普通寻路；一次侧移成功不等于已绕过整个底座。碰撞反向复核及局部绕行保持原相机参考系，不能在人物退让转身后回正，把离开障碍的方向误作出口；恢复普通路线后再按常规回正。`needs_scene_route` 表示候选不确定或实测不通，应接管实况选路，不表示实际无路；不能降阈值硬选、重复前推或只换时长。
- 修复自动绕障时，验收须从原受阻侧，用同一目标、地图参考、楼层与容差完成一次导航，记录实况检查、恢复动作与可靠定位的对应关系。手动绕行后自动回靠只证明回靠成功；依赖模块修改后正常重启并核对加载时间，控制脚本哈希一致不能代替依赖已更新。
- 常驻控制器版本 3 使用 `navigate_target`，具体请求见 [控制会话](session-control.md#直接指定地图目标)。已有会话支持 `treasure_action` 时也可提交 `step:{"type":"navigate","target":[x,y],"target_floor":"2F"}`。不要另起一个会抢输入的 CLI 任务；需要新版反馈或加载导航修复时，按控制会话的收尾流程正常停止、启动。`script_matches` 只比对控制脚本，不能证明已导入的导航依赖已加载修复。
- 定位、移动、受阻重规划与停滞检测留在本地循环，模型只处理目标、机关与失败后的路线选择。读取实际导航 `status`、`position_confirmed`、`position`、`moves` 和停止原因；外层请求 `ok`、按键发送成功或镜头改变不代表位置前进，只有 `arrived` 才代表导航到点，到点后仍须确认目标交互。
- 有已标定锚点时，入口定位也复用底图注册：当前源码的准备步骤 `map_marker` 调用 `focus_map_marker`，将屏外锚点分段拖入可点击区域，每次拖图后重新注册。不要把投影到屏外的坐标直接用于点击，也不要在地图已能注册时反复扫描图标。地形特征不足时保持匹配阈值；仅使用适用于当前入口的已标定恢复动作，仍失败就停止并重看状态。
- 高频开关地图按目标界面信号等待，使用配置中的地图键并留出动画稳定时间；优先复用 `TreasureGame._navigation_screen`。实测可能漏接开图键：等待超时且重新确认仍在主界面时只补按一次；未知界面、再次失败或退出地图超时立即停止，不回退到连续 Esc 的通用重试。相邻路点之间没有移动时可复用上次定位，发生移动、传送或布局改变后重新观察。
- 玩家坐标必须来自地图内的真实箭头；带白色圆环的屏外玩家提示不能用于定位。拖图时角色没有移动，坐标却大幅跳变，应检查是否误认边缘提示。地图注册成功但玩家不可见时仍可投影锚点，不能据此声称玩家已定位。
- 比较优化前后时使用相同路线、角色、分辨率和到达容差，分别记录开图、定位、关图及纠偏次数。一次更快的结果只能说明这次复测改善；重试次数和实际移动量的差异不能都归因于识别提速。路线入口、移动到达和奖励完成分别核验。
- 导航返回 `no_path`、`stalled`、定位失败或楼层连接缺失时，先查看结果再处理对应问题。`survey_limit` 须看 `survey_incomplete_reason`，扩图限额不等于已证无路；零移动时还需检查起点栅格连通性和目标遮挡，不能仅增加扩图额度。`control_unresolved` 即使有位移、靠近目标或出现交互提示，也没有确认到达；结合轨迹和当前对象判断后续动作。没有新位置、通路、目标或机关信息时，不重复同一导航，也不增加移动时长；手动处理门或障碍后重新定位再导航。跨层仍需提供已知连接，不能用二维坐标代替换层。
- 旧 `map_move` / `follow_waypoints` 与控制器的 `navigate(route,target_id)` 仍用于已有标定路线；它们要求对应底图、方向和起点，不能与无预录路线导航混淆。生研院旧路线的适用范围见 `assets/treasure_routes/life_sciences_institute/README.md`，不要求给新目标先补录整条路线。
- 没有可用地图但有目标地标和独立近距离交互条件时，可复用 `vision_navigate`；仅在现有导航无法表达机关或短距离交互时使用手动地标移动，不把连续看图按方向键作为普通地图导航的默认实现。

## 空间解谜与 3D 移动

- 接到「前往指定地点」类目标时，第一个导航动作是开图：读取任务金色标记与所在楼层，传送到离标记最近的锚点后再开始步行。禁止在未开图核对方向的情况下做多轮“转镜头+前走”试探——同一盲走模式连续 3 次无进展即停止。跟踪中的任务在地图上必有标记；地图上没有标记时先回任务列表确认追踪状态。
- 无底图标定的移动没有位移反馈：按住方向键固定秒数不等于发生了移动。每段移动后用快照确认变化（任务距离数字、地标位置或画面差异）；画面/距离无变化即被障碍挡住，立即换方向或绕行，不重复原方向按键。优先跟随屏幕内任务标记（菱形图标+距离米数）而非镜头猜测。跟随标记以距离数字收敛为准：递减＝方向正确，递增＝走反，收敛到个位数米且出现交互提示才算到达；标记是目标的世界投影，叠在前景 NPC 头上不等于目标就是该 NPC，禁止据此下达“找该角色对话”的指令。
- 多机关、可变通路或需要折返时，在本轮工作记录维护一条可直接接续的状态：`位置/地标 | 机关状态（未知项标未知） | 下一地标 | 预期变化 | 最近无效尝试`。机关编号只在当前关卡内有效；每次改变机关后验证通路变化并更新记录，不凭最近一张画面重新猜整条路线。
- 将路线拆到下一个可辨认的地标或转弯处。目标距离和穿墙标记只说明相对位置，不能证明前方可通行；还要核对楼层、遮挡和可走地面。攻略里的方向须对齐当前地标与机关状态后再用。星铁无法跳跃：任何高低差（台阶边缘、下沉广场、平台落差、护栏）都不能直走跨越，看似一步之遥也必须绕行找楼梯、坡道或升降机；下沉边缘的隐形护栏即此类设计，不要对着落差反复前推。
- 3D 转向优先使用已验证的相对鼠标移动，菜单使用定位点击。镜头回正、自动跟随或碰撞会改变画面方向：转向后先确认视野，再做一段移动；不要把未校准的转镜头、长距离斜走与交互混成一批。角度和移动时长在当前环境校准，不沿用其他设备的固定值。
- 每个新的手动或视觉移动段开始前，先把镜头对准下一段可走路线，恢复能看清前方地面与交互物的俯仰；已对准则直接走。拐弯、贴墙挤镜头、明显侧看或移动后转入搜索时重新回正，不能只因地图位移方向正确就一直歪着视角观察。Windows 前台通用地图导航现默认在每次正常路线选键前停键，按已实测的 Caps Lock 回正，复用本次地图定位已确认的参考坐标人物朝向，更新方向模型后再选键移动；初始化也先回正建立基准，原生回正不改变人物朝向，不额外识别半透明扇形；初始方向探测和碰撞复核保留原观测条件。M 大地图本身也显示相机扇形；本流程复用已确认的人物朝向。启用回正时不跨观测持续持键，`recenter_camera:false` 可显式关闭；后台和 CDP 尚未启用。不能在已选键的输入函数里临时插入回正。源码改动后须正常重启控制器加载，按键生效与整段导航到达分别核验。
- 星铁小地图为固定北上、玩家箭头旋转指示朝向（不随镜头旋转）：用小地图箭头读玩家绝对方位、用标记在小地图上的方位读目标方向，这是转向与导航的可靠基准。小地图同时渲染地形层：浅色连续区域＝可走地面，深灰黑条与白色轮廓线＝栏杆、围栏、墙体等障碍边界——寻路前先读小地图地形，玩家与目标之间隔着深色障碍条＝直线不可达，直接找开口或绕行，主画面看似能靠近（玻璃橱窗、低矮围栏）也已是封闭边界。本环境实测 `camera` delta 约 100≈13°（-400≈30°，90°≈±1200）；单次转向可能只部分生效，每次转向后用快照或小地图箭头确认实际角度，不足再补转，不连续盲发。转向单独成批，确认后再走移动段，不把转向与移动混在一批。任务距离数字突然变大时先考虑走反或楼层/垂直高度差（标记可能投影在玩家脚下），不要只怀疑识别错误。
- 相机俯仰卡死（俯视/仰视极端、贴墙贴边碰撞）恢复顺序：先 S 后退脱离碰撞，再反向 scroll 少量回调，仍异常则开关一次大地图复位镜头；不连续同向 scroll（易把俯仰推到极端）。scroll 语义随界面：地图内＝缩放，大世界＝俯仰。地图上点击任务标记需先放大视图再点，未放大时点击命中会偏移。贴墙死角时 `camera` 转向指令可能整体失效、连 `M` 开图也不生效：不连发转向指令，先长按 S 后退脱出死角、侧移到开阔处再转向，每个动作分开验证生效后再进行下一个。
- 连续两三次短距离修正仍停在同一障碍旁，且位置或可达性没有新变化时，停止微调。退回最近的开阔地或明确地标，重新看通路、地图或匹配阶段的攻略，再选择不同路线；已经确认撞墙时不必等满次数。下一次尝试必须说明改变了哪个条件，如起点、绕行侧、机关状态或角色朝向，不能只换一个相近的按键时长。
- 距离很近但交互未触发时，检查角色朝向、真实接近路径、遮挡和交互提示。转镜头不等于角色已转身；用一次短移动校正位置/朝向，再按提示交互，避免连续盲按。

## 区域搜索与近距交互

“在此区域寻找／调查／观察”等目标与地图黄圈通常表示搜索范围，中心只是进入区域的导航线索。进入范围或附近后就转入搜索；无需先精确到达中心，中心不可走也不应反复导航或把搜索任务直接判为失败。

- 在区域内以可见家具、货架、NPC、发光物或轮廓为候选，先观察当前可交互提示。出现普通“调查／交谈／拾取”等提示时，按界面实际按键或选项尝试，再看任务文字、对话或物品结果；不要求事前证明该物体一定是任务目标才交互。
- 当前没有提示时，回正视角，沿可走地面短距离换位并扫视，从不同侧面靠近候选物。移动、观察、交互交替进行；不要只站在圈中心反复OCR，也不要只沿任务菱形直推。镜头看向物体但未出现提示时，调整人物位置和朝向。
- 一次交互后核对是否推进；任务有变化就接续新阶段，无变化则换未检查的对象或位置。只记已检查的地标与结果，避免反复调查同一物体。区域明显搜索过仍无进展时，带任务原文和已查位置回查攻略。
- 地图导航的 `control_unresolved` 仍是“未确认到达”，但不妨碍停键后依据新画面接管区域搜索。任务范围内已有“调查”提示时优先检查该候选，不把导航终态当成禁止交互的条件；任务完成继续以交互后的游戏状态核验。

## AutoPlot 与普通战斗

优先通过已有小助手入口开启自动剧情。需要嵌入源码组件时，查看当前版本的 `tasks/tool/autoplot` 包或同名 `.py` 文件、`module/automation` 及其调用者，确认构造方式、选项、生命周期与输入后端；不能把往次代码片段当成当前接口保证。

已使用过的 AutoPlot 模式包含 `auto_skip`、`auto_click` 和 `auto_battle_detect_enable`，应按当前接口与用户偏好启用。Qt 定时器需要有效事件循环；只创建对象、调用 `start()` 后立即退出，或用长时间阻塞睡眠占住事件线程，都不能保证自动剧情持续执行。已有 GUI 事件循环就复用；独立进程才建立所需的 Qt 应用并处理事件。

自动对话只在剧情阶段持有输入控制。遇到特殊玩法、重要选择或人工选取目标时先停下，避免它与手动操作争抢输入。普通战斗则确认游戏内自动与加速状态后等待结算，能稳定自动推进时不逐回合介入；剧情控制组件中的战斗检测选项不能代替这一确认。

手动输入会停止自动剧情，且不会在批次结束后自行恢复；每段手动操作（对局、小游戏、探索）结束回到对话阶段时，先显式重新发送开启指令再交给自动跳过，避免对话长时间未跳过。任务跨越凌晨 4:00 每日刷新时会出现月卡等每日奖励弹窗，点击“领取”关闭并核对回到原界面后继续原任务，不当作输入或导航异常。

## 观察和等待的边界

以“当前阶段 → 已确定的一批操作 → 预期的新状态”组织执行，例如选择配置后确认、完成一组教学动作、等待战斗结算。批次可以跨越已验证且确定的转换；遇到未知选择、布局变化或异常就返回观察。

- 布局已知时只识别进度、按钮、交互提示或结算等必要区域，变化或失败时再取完整画面。只返回下一步需要的文字和位置，避免大段无关 OCR。
- 等待采用该阶段的合理初始间隔，再以小范围文字或图像信号判断是否可操作。持续动画期间降低观察频率；弹窗、回合数字、按钮激活或任务文本变化出现后及时继续。
- 长战斗或过场交给持续运行的任务，模型按阶段查看结果。工具调用内的输入、OCR 和等待总耗时应低于工具时限；必要时将启动与查询拆开或使用已有异步任务能力。
- 查询超时先查任务是否仍在运行，并读取最新画面/响应。对自建请求通道用请求编号对应结果，不把上一条响应当成当前状态，也不默认超时动作需要重做。
- 为定位而开图时，先保留地图截图或运行定位，再关图；不要将“开图→关图”合成只在末尾观察的批次。`ocr:false` 只是跳过文字识别，不等于地图定位；`observe:false` 会省掉该请求的观察。
- 协调执行者时同时核对最新请求编号、时间和控制器 `phase/active_request`。`idle` 且没有新请求表示没有游戏动作在执行，不能持续等待或汇报“正在寻路”；通知执行者提交下一明确动作或说明卡点，纠正后仍无推进再交接。已结束的执行者需要重新派发后续任务并确认有新请求，普通消息不表示已恢复执行。导航 `busy` 时看位置和移动次数是否更新，不能只凭进程存活判断有进展。
- 模型已知道规则且普通行动可低成本纠正时，选择达标方案即可。只在新规则、失败、重要资源取舍或识别矛盾处投入额外推理。

## 无进展时按证据排查

| 观察到的现象 | 优先检查和处理 |
|---|---|
| 画面可见，按钮不响应 | 当前是否仍在动画中、教程是否要求高亮步骤、是否有遮罩/弹窗、按钮是否已解锁；然后确认短按是否被接收。 |
| 多处输入都不响应或点位偏移 | 窗口焦点、鼠标捕获、权限、原图/预览比例、裁剪偏移和后端坐标约定。几何已验证正确且窗口没变化时，不反复猜 DPI。 |
| 按钮响应，但目标没有推进 | 查看是否还有确认、交付、升级、任务选项或解锁条件；属于机制问题时停止调整输入时长。 |
| OCR 缺字、数值矛盾 | 等过动画帧，缩小到相关区域重新识别，必要时查看图像；不基于模糊读数执行重要提交或消费。 |
| 重复败北或成绩不够 | 阅读胜利条件、阶段变化和失败信息；调整一个关键配置或策略，必要时定向查询规则，避免无变化重开。 |
| 进度数字停住 | 查看资源是否需提交、奖励是否需领取、任务是否需交付，以及下一段是否解锁；再决定是否补刷。 |
| 每步都慢 | 区分模型决策、进程/模型初始化、截图/OCR、输入重试、游戏动画和工具等待。优先减少重复启动与每次点击后的全屏识别，再缩短无效等待和过度分析。 |
| 凌晨 4 点后突然弹出月卡/每日奖励弹窗 | 每日刷新弹窗属预期：点“领取”关闭，确认回到原界面后继续原任务；不视为输入或导航异常。 |
| 对话一直不跳过、逐句播放 | 自动剧情已被之前的手动输入关闭且不会自行恢复；回到剧情阶段先显式重新开启自动跳过。 |

只有已经改变相关条件、得到新信息或确认是暂时延迟后才重试。同一现象持续出现就换观察或诊断方式；若确实依赖用户操作或外部状态，保留当前阶段并说明具体阻塞。
