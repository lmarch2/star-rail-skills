# 控制、识别与等待

在需要自定义控制、复用本地导航或 AutoPlot、处理空间解谜或排查无响应时读取。参数是校准起点，不是所有设备和活动的固定值；依据当前工具和源码接口执行。

## 先复用，再补最小控制

- 按 `march7th-assistant` 技能定位安装目录与能力，用其状态和运行记录接续已有任务。注册中的旧源码路径可能已不存在，先核对路径，不反复调用失效入口，也不全盘搜索。
- 一次观察可使用当前版本支持的 `--observe` / `--observe-image`；持续交互优先复用常驻 OCR、截图和输入对象，避免每步启动 Python、加载模型或重建游戏连接。
- 没有专用任务时，只补本次缺少的控制操作。批量输入与观察应可分开：若每条输入都自动附带全屏 OCR，应增加“不观察的输入批次＋末尾一次观察”，不能只把工具调用包装在循环里就认为已经减少识别。
- 临时控制程序使用独立目录，不因代做活动改动主项目、用户默认配置或安装新插件。只有重复出现且稳定的需求才值得形成通用脚本。
- 游戏与控制进程权限不匹配时先确认捕获、输入失败的具体位置，复用小助手提供的启动方式；必须出现的 UAC 或首次使用确认遵循相应工具规则，不能绕过。临时后台程序使用隐藏窗口。

## 按启动能力复用会话

持续交互复用常驻控制会话，启动前检查是否已有可用会话，保持单一游戏输入控制者。官方 `m7a.exe` 任务在 `elevation: task` 时免 UAC；直接运行的自定义 Python 控制器仍按自身权限启动。启动、必要的 UAC 确认、所有权交接、版本能力、请求格式、超时接续及退出统一见 [常驻会话用法](session-control.md)，本参考只说明控制策略与诊断。

## 输入校准和坐标

首次接管、窗口变化或恢复后，读取游戏窗口位置、截图原始尺寸与缩放，选择一个可逆动作确认输入生效。有效参数可在同一布局下复用。

- 将 OCR、截图与点击坐标放在同一坐标系。缩略图只用于观看；坐标换算按实际宽高比例分别进行，裁剪图还要还原裁剪偏移。输入后端若已经做坐标换算，不再重复换算。
- 快速点击偶发遗漏时，先核实界面可操作，再尝试带短暂停留的按下/释放。约 100～200 毫秒可作为鼠标起点；键盘交互仍漏触发时可适当延长，例如 300～500 毫秒。本次环境有效不代表数值对所有游戏阶段都必要。
- 正常使用当前后端支持的按键名称和输入方法。需要短按时优先直接使用有时长的点击接口；没有时，可在确认语义相同的后端使用同点按下/释放等实现。
- 3D 场景可能捕获鼠标，不能假设可直接点击 HUD；根据当前提示使用交互键或该界面提供的鼠标操作方式。
- 操作完成或控制异常退出时释放已按住的键和鼠标按钮。用户手动操作后重新读取当前状态，不能继续发送旧坐标序列。

## 本地定位与路线执行

- 移动前先检查本地可用能力。当前源码入口是 `utils/treasure_map.py` 的 `TreasureMapLocator`（地图定位）与 `follow_waypoints`（按路点移动、纠偏和停滞检测），调用示例是 `tasks/exploration/treasure.py` 的 `map_move`，路线数据位于 `assets/treasure_routes/`；适用范围与使用方式见仓库的 `assets/docs/Treasure.md`。优先复用这些代码与数据，确认实际版本和可调用入口，不另写同类导航。
- 区域、楼层、地图底图、分辨率及移动标定匹配，且路线覆盖当前目标时，优先调用已有路线；有本地定位时用它校正移动。定位、截图匹配和短距离纠偏留在本地循环，只向模型返回位置、路点进度和停止原因；到机关、分支或出现异常时再交回模型判断。
- 有已标定锚点时，入口定位也复用底图注册：当前源码的准备步骤 `map_marker` 调用 `focus_map_marker`，将屏外锚点分段拖入可点击区域，每次拖图后重新注册。不要把投影到屏外的坐标直接用于点击，也不要在地图已能注册时反复扫描图标。地形特征不足时保持匹配阈值；仅使用适用于当前入口的已标定恢复动作，仍失败就停止并重看状态。
- 高频开关地图按目标界面信号等待，使用配置中的地图键并留出动画稳定时间；优先复用 `TreasureGame._navigation_screen`。实测可能漏接开图键：等待超时且重新确认仍在主界面时只补按一次；未知界面、再次失败或退出地图超时立即停止，不回退到连续 Esc 的通用重试。相邻路点之间没有移动时可复用上次定位，发生移动、传送或布局改变后重新观察。
- 玩家坐标必须来自地图内的真实箭头；带白色圆环的屏外玩家提示不能用于定位。拖图时角色没有移动，坐标却大幅跳变，应检查是否误认边缘提示。地图注册成功但玩家不可见时仍可投影锚点，不能据此声称玩家已定位。
- 比较优化前后时使用相同路线、角色、分辨率和到达容差，分别记录开图、定位、关图及纠偏次数。一次更快的结果只能说明这次复测改善；重试次数和实际移动量的差异不能都归因于识别提速。路线入口、移动到达和奖励完成分别核验。
- 每次仍接近几像素也可能是在蹭障碍，不能仅用“坐标有变化”判断路线有效。持续明显低于标定预期时停止，查看地形并核对镜头、移动模式和输入节奏；不要直接增大时长或重复整段路线。当前执行器在连续三段推进不足预期四分之一时返回异常，仅比较大于到达容差的预期推进，保留终点附近的微调。实测轨迹回放能证明停止条件有效，不能代替改线后的实际到达验证。
- 本地定位仍可使用截图，无需把每步画面都传给模型。路线执行器跟随预设路点，不自动发现通路或理解机关；到达路点后仍须用交互提示、任务或奖励状态确认目标完成。
- 已验证范围与路线状态以仓库 `assets/treasure_routes/life_sciences_institute/README.md` 为准，使用方式见 `assets/docs/Treasure.md`，当前问题见 `docs/星铁导航卡点.md`；不能直接套用到未验证的区域或楼层。无适用标定、定位失败或连续停滞时，停止当前移动并转入下节的地标与空间判断；机关改变通路后重新确认路线适用性。
- 当前 `event_session.py` 已提供 `navigate` 入口，格式见 [控制会话](session-control.md)。它复用源码的 `load_route`、`run_route(..., navigate_to=...)` 和 `TreasureGame`，从路线起点走到指定点位并返回到达结果。接续旧进程仍以其已加载能力为准；保持单一输入控制者，不额外启动会抢输入的任务。

## 空间解谜与 3D 移动

- 多机关、可变通路或需要折返时，在本轮工作记录维护一条可直接接续的状态：`位置/地标 | 机关状态（未知项标未知） | 下一地标 | 预期变化 | 最近无效尝试`。机关编号只在当前关卡内有效；每次改变机关后验证通路变化并更新记录，不凭最近一张画面重新猜整条路线。
- 将路线拆到下一个可辨认的地标或转弯处。目标距离和穿墙标记只说明相对位置，不能证明前方可通行；还要核对楼层、遮挡和可走地面。攻略里的方向须对齐当前地标与机关状态后再用。
- 3D 转向优先使用已验证的相对鼠标移动，菜单使用定位点击。镜头回正、自动跟随或碰撞会改变画面方向：转向后先确认视野，再做一段移动；不要把未校准的转镜头、长距离斜走与交互混成一批。角度和移动时长在当前环境校准，不沿用其他设备的固定值。
- 连续两三次短距离修正仍停在同一障碍旁，且位置或可达性没有新变化时，停止微调。退回最近的开阔地或明确地标，重新看通路、地图或匹配阶段的攻略，再选择不同路线；已经确认撞墙时不必等满次数。下一次尝试必须说明改变了哪个条件，如起点、绕行侧、机关状态或角色朝向，不能只换一个相近的按键时长。
- 距离很近但交互未触发时，检查角色朝向、真实接近路径、遮挡和交互提示。转镜头不等于角色已转身；用一次短移动校正位置/朝向，再按提示交互，避免连续盲按。

## AutoPlot 与普通战斗

优先通过已有小助手入口开启自动剧情。需要嵌入源码组件时，查看当前版本的 `tasks/tool/autoplot` 包或同名 `.py` 文件、`module/automation` 及其调用者，确认构造方式、选项、生命周期与输入后端；不能把往次代码片段当成当前接口保证。

已使用过的 AutoPlot 模式包含 `auto_skip`、`auto_click` 和 `auto_battle_detect_enable`，应按当前接口与用户偏好启用。Qt 定时器需要有效事件循环；只创建对象、调用 `start()` 后立即退出，或用长时间阻塞睡眠占住事件线程，都不能保证自动剧情持续执行。已有 GUI 事件循环就复用；独立进程才建立所需的 Qt 应用并处理事件。

自动对话只在剧情阶段持有输入控制。遇到特殊玩法、重要选择或人工选取目标时先停下，避免它与手动操作争抢输入。普通战斗则确认游戏内自动与加速状态后等待结算，能稳定自动推进时不逐回合介入；剧情控制组件中的战斗检测选项不能代替这一确认。

## 观察和等待的边界

以“当前阶段 → 已确定的一批操作 → 预期的新状态”组织执行，例如选择配置后确认、完成一组教学动作、等待战斗结算。批次可以跨越已验证且确定的转换；遇到未知选择、布局变化或异常就返回观察。

- 布局已知时只识别进度、按钮、交互提示或结算等必要区域，变化或失败时再取完整画面。只返回下一步需要的文字和位置，避免大段无关 OCR。
- 等待采用该阶段的合理初始间隔，再以小范围文字或图像信号判断是否可操作。持续动画期间降低观察频率；弹窗、回合数字、按钮激活或任务文本变化出现后及时继续。
- 长战斗或过场交给持续运行的任务，模型按阶段查看结果。工具调用内的输入、OCR 和等待总耗时应低于工具时限；必要时将启动与查询拆开或使用已有异步任务能力。
- 查询超时先查任务是否仍在运行，并读取最新画面/响应。对自建请求通道用请求编号对应结果，不把上一条响应当成当前状态，也不默认超时动作需要重做。
- 模型已知道规则且普通行动可低成本纠正时，选择达标方案即可。只在新规则、失败、重要资源取舍或识别矛盾处投入额外推理。

## 无进展时按证据排查

| 观察到的现象 | 优先检查和处理 |
|---|---|
| 画面可见，按钮不响应 | 当前是否仍在动画中、教程是否要求高亮步骤、是否有遮罩/弹窗、按钮是否已解锁；然后确认短按是否被接收。 |
| 多处输入都不响应或点位偏移 | 窗口焦点、鼠标捕获、权限、原图/预览比例、裁剪偏移和后端坐标约定。几何已验证正确且窗口没变化时，不反复猜 DPI。 |
| 按钮响应，但目标没有推进 | 查看是否还有确认、交付、升级、任务选项或解锁条件；属于机制问题时停止调整输入时长。 |
| OCR 缺字、数值矛盾 | 等过动画帧，缩小到相关区域重新识别，必要时查看图像；不基于模糊读数执行重要提交或消费。 |
| 重复败北或成绩不够 | 阅读胜利条件、阶段变化和失败信息；调整一个关键配置或策略，必要时定向查询规则，避免无变化重开。 |
| 进度数字停住 | 查看资源是否需提交、奖励是否需领取、任务是否需交付，以及下一段是否解锁；再决定是否补刷。 |
| 每步都慢 | 区分模型决策、进程/模型初始化、截图/OCR、输入重试、游戏动画和工具等待。优先减少重复启动与每次点击后的全屏识别，再缩短无效等待和过度分析。 |

只有已经改变相关条件、得到新信息或确认是暂时延迟后才重试。同一现象持续出现就换观察或诊断方式；若确实依赖用户操作或外部状态，保留当前阶段并说明具体阻塞。
